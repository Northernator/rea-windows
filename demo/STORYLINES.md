# REA Windows demo directions

Assumptions: 28–30 seconds, 1920×1080 at 30 fps, no voiceover, free bundled action sounds, source-backed Windows UI and CLI evidence. No paid services, generated screenshots, or claims of measured speed.

Five sketches: result-first native window with evidence match; one evidence packet travelling from app to CLI; observation/action/read-back as a continuous camera move; a type-led argument for Windows accessibility; a test report rebuilding into an application window.

## Selected: The proof is in the window

Recommended because one recognisable Windows task makes the provider's purpose visible. Device: result first. Form: match cuts between the actual application and its captured evidence, ending on the same result.

First two seconds: an enlarged crop of the tested application's completed result fills the frame beside the line “A real Windows window”. The camera establishes the full native window, then follows its observed value into the CLI evidence.

Beats: completed app result → inspect the native tree → name REA Windows → run an explicit action → read back the actual result → return to the native app → repository end card.

Look: actual Windows UI on an opaque light grey stage; black type, saturated orange for the one action; terminal evidence uses an opaque graphite surface, not floating cards. Sound: bundled click on action, short whoosh on viewpoint changes, chime on verified result. No synthetic music generator.

## Alternative: Follow the evidence

Device: one object across apps. Form: an object-to-object chain following an observed value from native application to UI Automation tree to evidence envelope. First two seconds: the real result text is isolated at large size, then its actual node path appears. Beats: value → path → action → before/after envelopes → digest → repository. Look: white technical document with measured orange selection marks. Sound: restrained ticking and paper-like clicks.

## Alternative: One window, one take

Device: a cursor does the work. Form: one continuous camera move over the actual native window and its real terminal output. First two seconds: the tested application's window already occupies most of the frame as the viewpoint moves to its editor or control. Beats: observe → choose path → explicit action → read back → evidence saved → pull out to REA Windows. Look: full-frame native UI shifting into a full-frame terminal, with no invented controls. Sound: click, typing cue only during command text, confirmation chime.
